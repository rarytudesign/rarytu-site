# Как восстановить сайт rarytu.com без ИИ

Этот файл лежит внутри каждого бэкапа (папка `docs/`). Если что-то случилось, начни отсюда.

## Что есть в бэкапе

Бэкап делается в админке: rarytu.com/admin/ → вкладка Site backups → Save backup. Получается ZIP-архив `rarytu-backup-vNN-дата.zip`.

В архиве весь сайт целиком, ничего не нужно докачивать:

- страницы на двух языках: `index.html`, `en/`, `ru/`;
- стили, скрипты, шрифты, картинки, видео, оба резюме: `assets/`;
- все тексты сайта в редактируемом виде: `content/` (из них собираются страницы);
- админка: `admin/`;
- иконки сайта и превью ссылок: `favicon.ico`, `apple-touch-icon.png`, `site.webmanifest`, `assets/img/share.jpg`;
- файл домена `CNAME` (в нём написано rarytu.com);
- документация: этот файл, `docs/AI-CONTEXT.md` (вводная для ИИ), `docs/cms/` (подробный журнал работы), `README.md`;
- `backup.json`: номер версии, дата, контрольная сумма.

Чего в бэкапе нет и быть не может (это хранится в аккаунтах, а не в файлах):

- пароли от GitHub, Spaceweb, Cloudflare, почты;
- ключ GitHub для админки (он лежит в репозитории в зашифрованном виде, без твоего логина и пароля от админки он бесполезен);
- история всех изменений (в архиве только состояние сайта на момент бэкапа);
- настройки домена (DNS) у регистратора, настройки GitHub Pages.

Правило: **делай бэкап после каждой серии правок** и храни 2–3 последних архива в двух местах (компьютер + облако или флешка). Архив весит около 70 МБ.

## Аккаунты, от которых зависит сайт

| Что | Где | Зачем |
|---|---|---|
| GitHub, аккаунт **rarytudesign** | github.com | Там лежит сайт (репозиторий **rarytu-site**) и оттуда он показывается (GitHub Pages). Почта для восстановления: rarytudesign@gmail.com |
| Домены **rarytu.com** и **rarytu.ru** | Spaceweb (sweb.ru) | Адрес сайта. Продлевать каждый год, автопродление должно быть включено. Для .ru нужна идентификация через Госуслуги |

Записи домена rarytu.com в Spaceweb (DNS), если их когда-нибудь придётся ввести заново:

- 4 записи **A** для `rarytu.com`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
- запись **CNAME** для `www`: `rarytudesign.github.io`;
- запись **TXT** `_github-pages-challenge-rarytudesign`: значение выдаёт GitHub в настройках аккаунта (не репозитория): Settings → Pages → Verified domains;
- rarytu.ru: в Spaceweb «Переадресация» на `https://rarytu.com`.

## Ситуация 1. Я (или кто-то) что-то сломал правкой

Самый частый случай. Всё делается в браузере.

1. Открой rarytu.com/admin/ и войди.
2. Вкладка **Site backups** → **Restore backup** → выбери последний хороший архив.
3. Через 1–2 минуты сайт станет таким, как в архиве. Сама админка при этом не откатывается.

Если в админке есть неопубликованный черновик, который всё ломает, нажми **Discard draft**.

## Ситуация 2. Админка не открывается, а сайт нужно вернуть

Через сайт GitHub, без админки:

1. Войди на github.com (аккаунт rarytudesign) и открой репозиторий **rarytu-site**.
2. Распакуй архив бэкапа на компьютере.
3. В репозитории: **Add file → Upload files**, перетащи туда содержимое распакованной папки (не саму папку, а то, что внутри). GitHub загружает до 100 файлов за раз: если файлов больше, загружай по папкам (`en`, `ru`, `assets/img` и т.д.).
4. Внизу **Commit changes**. Через 1–2 минуты сайт обновится.

Если нужно вернуть именно старую версию, проще: в репозитории вкладка **Commits**, найди нужную дату, открой коммит. Каждая публикация из админки и каждый бэкап там видны.

## Ситуация 3. Репозиторий удалён или GitHub-аккаунт потерян

1. Создай (или восстанови по почте) аккаунт GitHub. Лучше с тем же именем **rarytudesign**: админка настроена на адрес `rarytudesign/rarytu-site`. С другим именем сайт заработает, а админку нужно будет перенастроить (одна строка в `admin/cms/github.js`, это может сделать ИИ по файлу `docs/AI-CONTEXT.md`).
2. Создай публичный репозиторий **rarytu-site**.
3. Загрузи в него содержимое архива (как в ситуации 2, шаги 2–4).
4. Settings → **Pages**: Source = Deploy from a branch, Branch = `main`, папка `/ (root)`, Save.
5. Settings → Pages → **Custom domain**: `rarytu.com`, Save. Когда проверка пройдёт, поставь галочку **Enforce HTTPS**.
6. Если аккаунт новый: в настройках аккаунта (Settings → Pages → Add a domain) заново подтверди домен, GitHub выдаст новую TXT-запись, добавь её в Spaceweb.
7. Для админки: создай ключ GitHub (github.com/settings/personal-access-tokens/new: срок 1 год, только репозиторий rarytu-site, права Contents: Read and write), открой rarytu.com/admin/, вставь ключ и задай логин и пароль.

## Ситуация 4. Переехать с GitHub на другой хостинг

Сайт статический: это просто папка файлов, никакой базы данных и сервера.

1. Купи любой хостинг для статических сайтов (Timeweb, Beget, Netlify и т.п.).
2. Загрузи туда содержимое архива через панель хостинга или FTP.
3. В Spaceweb поменяй DNS-записи rarytu.com на те, что даст новый хостинг.

Сайт будет работать как раньше. Не будет работать только админка: она пишет изменения через GitHub. Править сайт тогда можно файлами в `content/` (нужна пересборка, см. `docs/AI-CONTEXT.md`) или попросить ИИ.

## Посмотреть сайт из архива на своём компьютере

Распакуй архив, открой Терминал в этой папке и выполни `python3 -m http.server 8000`, затем открой в браузере http://localhost:8000. Двойной клик по `index.html` тоже работает, но видео может не играть.

## Продолжить работу с ИИ (Claude или другим)

Дай ему архив (или доступ к репозиторию rarytudesign/rarytu-site) и попроси сначала прочитать `docs/AI-CONTEXT.md`. Там всё, что нужно знать о сайте, правилах и о том, как его править. Подробная история всех решений: `docs/cms/PROGRESS.md`.
